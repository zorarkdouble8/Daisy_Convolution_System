# Memory, asset, and protocol structure

## DSP memory

The real 512-point FFT takes 512 real `float`s in time domain. Its packed output
also has 512 floats: `DC, Nyquist, Re(1), Im(1), ... Re(255), Im(255)`. DC and
Nyquist are separate real values; bins 1–255 are complex pairs. This is exactly
the layout generated by the offline converter and accepted by CMSIS
`arm_rfft_fast_f32`.

| Storage | Location | Floats | Bytes |
|---|---:|---:|---:|
| IR spectra, 94 x 512 | SDRAM | 48,128 | 192,512 |
| input-spectrum ring, 94 x 512 | SDRAM | 48,128 | 192,512 |
| time buffer + accumulator | internal RAM | 1,024 | 4,096 |
| overlap | internal RAM | 256 | 1,024 |

The ring slot for the new input is FFT'd in place. For partition `p`, the core
uses `H[p] * X[(current - p) mod partition_count]`, adds all spectra, inverse
transforms, adds the saved 256-sample tail, then saves the new tail. CMSIS's
inverse real FFT already supplies its inverse scaling, so it is not divided by
512 again.

## `DIRF` asset

The 256-byte little-endian header begins with `DIRF`, version 1, format 1,
32,000 Hz, partition size 256, FFT size 512, and a maximum of 94 partitions.
Payload bytes are consecutive packed float32 spectra. The parser explicitly
reads byte offsets, requires bytes 52–255 to be zero, validates both zlib CRC32
values, dimensions, finite normalization metadata, and all finite spectrum
components. The normalization factor is metadata only; spectra are already
normalized. Reverb intentionally applies its separate 64x wet playback gain
after convolution and clamps output to `[-1, 1]`; it does not multiply by this
metadata value again.

The default church file is 256 + 94 x 512 x 4 = **192,768 bytes** and fits in
the QSPI slot `0x000000–0x02FFFF` (192 KiB / 48 x 4 KiB erase sectors).

## Temporary USB uploader protocol

Frames are little-endian:

```
DIRU | command:u32 | sequence:u32 | payload_length:u32 | crc32:u32 | payload
```

CRC32 covers `command`, `sequence`, `payload_length`, and payload. Maximum
payload is 1,024 bytes. Numeric commands are `HELLO=1`, `BEGIN=2`, `DATA=3`,
`COMMIT=4`, `STATUS=5`, `ACK=0x8000`, and `ERROR=0x8001`. Statuses include 0
(success), bad-frame, bad-sequence, bad-asset, too-large, incomplete,
programming, flash-failure, busy, and receive-overflow.

The client uses stop-and-wait with a two-second frame timeout and three sends.
Duplicate DATA sequence numbers are ACKed without appending again. USB callbacks
only enqueue fragments; foreground code reconstructs frames and performs QSPI
work. At COMMIT the complete staged SDRAM asset is CRC/header validated, payload
is erased/written/verified first, then the header is written and the whole stored
asset is revalidated. Therefore a failed erase/write can invalidate the older
single-slot asset; reverb rejects incomplete data.

The uploader LED slowly blinks when it is ready to receive an asset and rapidly
blinks after successful QSPI write, readback, and full stored-asset validation.
